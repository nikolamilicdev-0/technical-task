# Loom scripts

Two recordings of at most five minutes each. Before recording: run `pnpm bootstrap --local`, set an AI key, start `pnpm dev`, sign up once, and keep one Markdown document with a few headings plus a short PDF at hand. Keep a second provider's key ready for the swap.

## Video 1: app walkthrough

| Time | Show                                                                                                                                                                                                                                  | Say                                                                                                                                                                                                                                                                                             |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00 | README top and feature list                                                                                                                                                                                                           | What it is: a knowledge base that answers from your own documents with citations. Stack in one sentence. The four ideas worth watching: RLS as the boundary, a durable queue in Postgres, hybrid retrieval, a provider-agnostic AI layer.                                                       |
| 0:40 | Terminal: `pnpm bootstrap --local` summary, the AI key in `.env`, `pnpm dev`, then `curl localhost:4000/api/health/ready`                                                                                                             | One command sets up dependencies, `.env`, the local Supabase stack, migrations and types; hosted projects and a no-CLI path work too. Readiness checks the database and the vector column size.                                                                                                 |
| 1:20 | Browser: create a Markdown document with headings, upload the PDF, watch Queued → Indexing → Ready; open the status bar                                                                                                               | Saving returns at once; the worker claims the document from the table itself, chunks it along headings (400-token target, `Title › Heading` breadcrumbs) and embeds it. Editing one paragraph re-embeds only its chunks.                                                                        |
| 2:10 | Chat: ask a question, let it stream, click a `[1]` chip, open the source card; ask a follow-up; press Stop mid-answer; reload                                                                                                         | Vector and full-text search run in parallel and are fused with RRF; the prompt allows only the numbered sources. The follow-up is rewritten into a standalone query (point at the API log line). Stop keeps the partial answer, and the citations survive a reload because they are a snapshot. |
| 3:00 | `.env`: switch the provider (for example OpenAI to Gemini, models blanked), restart the API, show the "Re-queued documents" log line, ask again                                                                                       | Only environment variables change. Chat and embeddings are configured separately; a new embedding model changes the signature, so the worker re-indexes the library by itself and vector spaces never mix.                                                                                      |
| 3:40 | Usage page                                                                                                                                                                                                                            | Every provider call is metered: chat, embeddings and query rewrites, per day and per model; estimates are flagged when a provider reports no usage.                                                                                                                                             |
| 4:10 | Code: `packages/contracts/src/documents.ts` → `ZodBody` in `documents.controller.ts` → the web form's resolver; then `supabase/migrations/20260929100100_documents.sql` (policies, column grants) and `SupabaseClientFactory.forUser` | One zod schema validates both sides. Every user request runs through a client that carries the user's JWT, so Postgres RLS decides visibility; the secret key only serves the worker, the usage recorder and the readiness probe.                                                               |
| 4:50 | README "What I'd improve"                                                                                                                                                                                                             | Next steps: a reranker with an evaluation set, ingestion on its own process and queue, and a Playwright smoke test.                                                                                                                                                                             |
